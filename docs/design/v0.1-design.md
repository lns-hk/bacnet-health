Status: **Draft for owner review** · Target release: `0.1.0a1` (pre-release) · Date: 2026-11-08

## 1. Instrument statement

bacnet-health is a **measurement instrument** used on a live control network. Every report states what the tool did to
the network and what it could and could not see.

### 1.1 What the tool transmits (complete list)

| Layer | Message | When | Code |
|---|---|---|---|
| APDU unconfirmed | Who-Is (ranged) | `scan` discovery | service choice 8 |
| APDU confirmed | ReadPropertyMultiple | property read, if the device supports it | service choice 14 |
| APDU confirmed | ReadProperty | property read fallback, and the first read of protocol-services-supported | service choice 12 |
| BVLC | Read-Broadcast-Distribution-Table | BBMD audit | 0x02 |
| BVLC | Read-Foreign-Device-Table | BBMD audit | 0x06 |
| BVLC | Original-Unicast-NPDU / Original-Broadcast-NPDU | carriers for the APDUs above | 0x0A / 0x0B |
| BVLC | Register-Foreign-Device | **only** after a typed FDR confirmation | 0x05 |
| BVLC | Distribute-Broadcast-To-Network | **only** in FDR mode, to carry Who-Is | 0x09 |
| NPDU | routed request to DNET/DADR | **only** with `read-remote` | — |

Nothing else is ever sent. In particular the tool never sends WriteProperty(-Multiple), DeviceCommunicationControl,
ReinitializeDevice, Create/DeleteObject, Add/RemoveListElement, AtomicWriteFile, SubscribeCOV(-Property),
ConfirmedPrivateTransfer, Write-BDT, Delete-FDT-Entry, TimeSynchronization, or any network-layer message
(including Who-Is-Router-To-Network).

**Honesty note (shown in the report and in the GUI risk text).** Register-Foreign-Device is not strictly "read-only".
It makes the BBMD create an FDT entry for the tool's address, with a TTL. The tool sets the shortest practical TTL
(60 s [PROVISIONAL]) and lets it expire; it does not send Delete-FDT-Entry. All other transmissions leave no
state on any device, apart from the normal transaction state while a request is open.

The transmit allow-list is enforced in code at one choke point (`wire.tx_guard`). Any frame the encoder builds is checked
against the list above before `sendto()`. A unit test and the self-capture test (§9.4) both verify this.

### 1.2 Traffic budget

Before any transmission, the tool computes a **budget preview** and shows it in the confirmation step.

- Who-Is count, the chunk plan, and the minimum spacing between Who-Is.
- Expected I-Am replies: an upper bound based on the chunk cap.
- Read requests: per-device request count × number of devices (an estimate until discovery finishes).
- BBMD probes: one Read-BDT per local responder, plus one Read-FDT per BBMD found.
- Peak packets per second sent, and estimated duration.

During the run the tool enforces the budget. If actual traffic would exceed the preview by more than 20%
[PROVISIONAL], the run pauses and asks the user before continuing.

Default rate limits [PROVISIONAL]:

| Limit | Default |
|---|---|
| Gap between Who-Is | ≥ 1.0 s |
| Global confirmed-request rate | ≤ 5 req/s |
| Requests in flight per device | 1 |
| Requests in flight per remote network (DNET) | 1 globally, ≤ 1 req/s |
| APDU timeout / retries | 3 s / 1 retry (a device that fails twice is marked unresponsive, not hammered) |
| Read-BDT / Read-FDT | 1 per target, ≤ 2/s, no retry |

### 1.3 Observation limits (vantage)

What a passive capture can see depends on where the laptop is plugged in.

| Vantage | How to get it | What is visible |
|---|---|---|
| `self` | `listen` (UDP socket on 47808) | Broadcasts on the local subnet + unicast addressed to the tool. **No** device-to-device unicast. |
| `access` | pcap on a normal switch port | Same as `self`, plus non-BACnet broadcasts. |
| `span` | pcap on a SPAN/mirror port, or inline tap | All traffic the mirror delivers. |
| `unknown` | imported pcap of unknown origin | Assumed `access` unless the content shows otherwise. |

The tool infers vantage. If the capture contains BACnet unicast between two hosts that are not the capturing host,
vantage is `span`; otherwise `access`. The user can override the inferred value in the GUI or CLI, and the override is
recorded in the report.

Every finding declares the minimum vantage it needs (§4). If the vantage is too low, the finding is not raised. The
report lists it under "Checks not performed (insufficient vantage)", so an absent finding is never mistaken for a
healthy network.

### 1.4 Run order in `audit`

`audit` runs `listen` (default 10 min) first, then `scan`, then `report`. Listening first measures the network's
baseline before the tool sends anything. Without it, the tool's own Who-Is and I-Am replies would show up in the
broadcast statistics. The tool's own frames are tagged at transmit time and excluded from every passive metric.

## 2. Safety case (FMEA for active operations)

Severity (S), likelihood (L) and detectability (D) are each scored 1–5; RPN = S×L×D. All scores are [PROVISIONAL]
and are re-scored after lab and field data.

| # | Failure mode | Cause | Effect on site | S | L | D | RPN | Mitigation / default |
|---|---|---|---|---|---|---|---|---|
| F1 | I-Am storm caused by the tool | Global or overly wide Who-Is on a dense network | Broadcast surge, slow workstations, possible MS/TP router congestion | 4 | 3 | 2 | 24 | Never send a global Who-Is. Adaptive chunking (§3.2) bounds each burst. ≥ 1 s gap. |
| F2 | Who-Is propagates beyond the subnet | Local BBMD forwards the tool's Original-Broadcast to all peers | Storm across buildings or campus | 5 | 3 | 3 | 45 | Budget preview warns when a local BBMD is known (from `listen` or an earlier probe). With a known BBMD, the default chunk cap drops 4×. The report states that broadcasts may have been distributed. [TBV: whether to switch to unicast-only discovery when a BBMD is present.] |
| F3 | MS/TP saturation | Reads routed to slow MS/TP trunks | Control latency, token loss | 5 | 2 | 3 | 30 | `read-remote` off by default. When on: 1 request in flight per DNET, ≤ 1 req/s, abort the network after 2 consecutive timeouts. |
| F4 | Fragile device fault | Device mishandles an RPM or an unknown BVLC function (Read-BDT on a non-BBMD) | Device reboot or comms loss | 5 | 1 | 4 | 20 | Read protocol-services-supported first (one RP), and use RPM only if the bit is set. Read-BDT is a standard function that every BACnet/IP node must answer with a NAK [TBV, Annex J]. Keep a vendor quirk list in `data/quirks.json` that skips or downgrades probes. |
| F5 | Tool broadcasts on the wrong network | Laptop has both Wi-Fi (corporate IT) and Ethernet (BMS) | BACnet scan of the client's IT network | 4 | 3 | 2 | 24 | Auto-pick prefers wired, RFC 1918, no-default-route interfaces. The user always confirms "Will broadcast on 192.0.2.255 via Ethernet 2". Only directed subnet broadcast is used, never 255.255.255.255 (which follows the default route). |
| F6 | IDS / BMS alarm triggered | Scan resembles reconnaissance | Client SOC incident, loss of trust | 3 | 3 | 1 | 9 | A rules-of-engagement record (who authorised, scope, time window) is required in the GUI before the first scan of a site and printed on the report. A pre-scan reminder tells the user to notify the site. |
| F7 | FDR leaves residue | FDT entry not removed | Stale entry until TTL expiry | 1 | 5 | 1 | 5 | TTL 60 s; the report records it. |
| F8 | Port conflict corrupts another tool | Sharing 47808 with BMS software | Missed or misrouted packets | 3 | 2 | 1 | 6 | Exclusive bind (D9). On Windows use `SO_EXCLUSIVEADDRUSE`; never set `SO_REUSEADDR`/`SO_REUSEPORT`. If the port is busy, refuse with a plain-English message naming the owning process where the OS allows it. |
| F9 | Windows Firewall blocks replies silently | User clicked Cancel on the firewall prompt | Empty scan, falsely reported as "no devices" | 3 | 3 | 4 | 36 | Pre-flight check of inbound reachability (self-test; method [TBV]), and report "0 devices" only together with "inbound UDP 47808 verified". [TBV: a reliable no-admin self-test on Windows.] |
| F10 | User cannot stop the run | Long scan | Prolonged load | 3 | 2 | 1 | 6 | Big Stop button / Ctrl-C. Transmission stops within 100 ms; no new requests after stop; partial results are kept and marked incomplete. |

Additional controls:

- **Dry run.** The GUI "Preview packets" step, or `--dry-run` on the CLI, lists every frame that would be sent, with
  a hex dump.
- **Kill switch.** One cancellation token checked before every `sendto()`.
- **Network write lock.** None of the wire encoders for prohibited services exist in the codebase. They cannot be
  enabled by configuration.

## 3. Active operations — detailed behaviour

### 3.1 Socket and interface

- Bind `0.0.0.0:<port>` exclusively on macOS and Linux. A socket bound to a unicast address does not receive subnet
  broadcasts there. Frames are filtered by the selected interface's subnet. On Windows, bind the interface IP
  [TBV: Windows broadcast delivery to an IP-bound socket].
- Interface enumeration uses `ctypes`: `getifaddrs` on macOS/Linux, `GetAdaptersAddresses` on Windows. Both are stdlib,
  so there is no dependency.
- Broadcasts go to the directed broadcast address of the selected interface only.

### 3.2 Adaptive segmented Who-Is

Instance space is 0–4 194 302. The value 4 194 303 is the wildcard and is not used in ranges.

```
chunk = 1024                       # [PROVISIONAL] initial size
while cursor <= 4_194_302:
    send Who-Is(low=cursor, high=min(cursor+chunk-1, MAX))
    collect I-Am for window W = 3 s  [PROVISIONAL]
    n = replies in window
    if n > 64:  chunk = max(chunk // 4, 16)       # dense: shrink hard
    elif n > 32: chunk = max(chunk // 2, 16)
    elif n < 8:  chunk = min(chunk * 2, 262_144)  # sparse: grow
    cursor += previous chunk; wait max(1 s, rate limiter)
```

The worst-case burst is bounded by the number of devices inside one chunk. Starting small bounds the first burst. The
plan and the actual chunk sequence are both recorded in JSON. Late I-Ams, arriving outside their window, are still
recorded and attributed to the correct range.

Unicast mode (`--target`, or a GUI target list) sends a ReadProperty for the Device object-identifier at instance 4 194 303 (the standard "unknown instance" device reference)
to each target IP. This finds devices that do not answer broadcasts. [TBV: support level across vendors; fall back to
a unicast Who-Is.]

### 3.3 Property read set

Per local device, in this order:

1. RP `protocol-services-supported` (97). This decides whether RPM is used.
2. RPM, or RP one property at a time, for: `object-name` (77), `vendor-name` (121), `model-name` (70),
   `firmware-revision` (44), `application-software-version` (12), `protocol-version` (98), `protocol-revision` (139),
   `location` (58), `description` (28), `system-status` (112), `local-date` (56), `local-time` (57),
   `utc-offset` (119), `database-revision` (155), `max-segments-accepted` (167), `object-list` array index 0 (76).

These come free from the I-Am: `vendor-identifier`, `max-apdu-length-accepted`, `segmentation-supported`.

If the RPM response would exceed the device's max-APDU and the device does not support segmentation, the request is
split into smaller RPMs. Unknown-property or optional-property errors are recorded as "not supported". They are never
treated as a communication error.

The host clock is recorded at the moment `local-time` is read, so clock skew can be computed. The tool's clock source is
shown in the report. Skew is only meaningful if the laptop is NTP-synced; the GUI checks and warns.

### 3.4 BBMD audit

1. For each local I-Am responder (unique IP:port), send Read-BDT once.
   - **Read-BDT-Ack** → BBMD; store the BDT.
   - **BVLC-Result 0x0020 (Read-BDT NAK)** → not a BBMD.
   - **Timeout** → unknown; record it, no retry.
2. Also add BBMD candidates seen passively: sources of Forwarded-NPDU, targets of Register-Foreign-Device. Add any
   addresses the user gives explicitly.
3. For each BBMD, send Read-FDT once.
4. Build the topology graph (§3.5).
5. `follow-bdt` (typed confirmation): send Read-BDT to each peer listed in local BDTs, once each, no recursion beyond
   one hop [PROVISIONAL]. This lets the tool check BDT symmetry.

NAT-traversal BBMDs (the Annex J NAT extension, [TBV clause]) can show a global address in their own BDT entry. The
tool records the discrepancy between observed source address and BDT self-entry as information rather than an error,
unless other evidence contradicts it.

BACnet/IPv6 (Annex U) and BACnet/SC are **out of scope** for v0.1 and stated as such in the report.

### 3.5 Topology model

Nodes are subnets (from interface or BDT masks), BBMDs, foreign devices and routers (from routed I-Am SNET).
Edges are BDT entries (directed, with broadcast distribution mask) and FDT registrations.

For each subnet S, the tool simulates an Original-Broadcast originating in S:

- **One-hop** distribution (mask all-ones): the BBMD unicasts a Forwarded-NPDU to the peer BBMD, which re-broadcasts
  locally.
- **Two-hop** distribution (directed-broadcast mask): the packet goes straight to the peer subnet's broadcast address.

The result is how many copies each subnet receives. A healthy network has exactly 1 per reachable subnet. More than 1
means duplicate distribution; 0 means unreachable. [TBV: exact Annex J forwarding rules, including the "do not
re-forward Forwarded-NPDU" rule.]

The prediction is cross-checked against passive evidence. If `listen` or a pcap saw the same NPDU (same source, same
payload hash within 50 ms) twice, the duplicate-BBMD finding moves from Inferred to Observed.

## 4. Finding catalogue (v0.1)

Each finding has: ID, group, title, spec basis, trigger, severity rule, confidence, minimum vantage, evidence
attached, and a falsifier (what would prove it wrong). All numeric thresholds are [PROVISIONAL]. The spec column
gives the clause area; exact sub-clauses are [TBV] against 135-2020.

Severity rule summary:

- **Critical**: Observed, plus direct security exposure or a control disruption happening during the capture.
- **High**: likely to affect control or security now.
- **Medium**: degrades reliability or maintainability.
- **Low**: hygiene.
- **Info**: inventory facts.

Inferred findings are capped at High.

## 5. Data model and JSON

- One JSON document per run: `bacnet-health-<kind>-<UTC timestamp>.json`, where kind is scan, listen, analyze or audit.
- Top level:
  - `schema_version`
  - `tool` (name, version, git commit, Python version, OS)
  - `run` (command or profile, start/end UTC, host clock and NTP state, interface, port, vantage, rules-of-engagement
    record, confirmations given)
  - `budget` (preview vs actual)
  - `inputs` (pcap path + SHA-256)
  - `devices[]`
  - `bbmds[]`
  - `topology`
  - `metrics` (raw counters and time series for calibration, per D12)
  - `findings[]`
  - `checks_not_performed[]`
  - `limitations[]`
- `schema_version` follows semver. The JSON Schema file ships with the package and is validated in tests.
- Finding object fields: `id`, `group`, `severity`, `confidence`, `vantage_required`, `title`, `explanation` (plain
  English), `recommendation`, `spec_refs[]`, `evidence[]`, `thresholds_used{value, provisional}`, `falsifier`.
  `evidence[]` entries point to frame numbers and timestamps for pcaps, or request/response pairs for scans.
- Device identity for diffing is `(device instance, vendor-id)`. The diff reports added and removed devices, changed
  firmware/database-revision/object-name, and findings that are new, resolved or persisting.

### 5.1 Redaction

`--redact` (GUI: "Redact for sharing") uses a per-run random key held only in memory. It applies HMAC-based consistent
pseudonyms:

- IPv4 → a deterministic address in 192.0.2.0/24, 198.51.100.0/24 or 203.0.113.0/24. Private vs public is preserved,
  so SEC-004/BBMD-006 still read correctly.
- Strings (object-name, location, description, site/org fields) → `name-<4 hex>`.
- MACs are pseudonymised.

Kept as-is: instance numbers, vendor/model/firmware, counts, timings.

The redacted pcap rewrites IP headers (with checksums recomputed), BVLC/NPDU addresses, and character strings inside
APDUs where the decoder recognises them. Frames that cannot be decoded are dropped and counted. The report says so,
because a partially-redacted frame is a leak.

## 6. Reports

### 6.1 HTML

The HTML report is one self-contained file: inline CSS, inline SVG charts, base64 logo, no JS required to read it
(optional JS only for table sorting). It is print-ready on A4 and Letter.

Sections:

1. Cover: site, prepared-by, organisation, logo, date, tool version.
2. Executive summary. Counts by severity, the top five findings in plain English, and one paragraph on overall
   condition. No score (D14).
3. Scope and rules of engagement: authorisation, time window, interface, vantage, what was sent (budget actual).
4. Findings, grouped by severity. Each has an explanation, a recommendation, evidence and spec references.
5. Checks not performed, and why.
6. Inventory: devices, BBMDs, topology diagram (SVG).
7. Methodology and limitations, including the "[PROVISIONAL] thresholds" statement and the pre-release statement (D17).
8. Appendix: reproducibility (command/profile, input SHA-256, tool version) and raw metrics charts.

White-label fields come from a profile or config: `org`, `logo`, `prepared_by`, `site`, `client`, `accent_colour`.
The footer always reads "Generated by bacnet-health vX.Y.Z".

### 6.2 Terminal

The terminal summary shows severity counts, a one-line summary per finding, and the paths of the JSON/HTML files.

## 7. Decoder and file formats

- Written from the specs, not ported from other libraries:
  - pcap (classic, µs/ns, both endiannesses) and pcapng (SHB/IDB/EPB/SPB, multiple interfaces, if_tsresol);
  - Ethernet, 802.1Q, Linux SLL/SLL2, IPv4 with reassembly of fragmented UDP, UDP;
  - BVLC (Annex J), NPDU (Cl. 6), APDU (Cl. 20), application/context tag encoding (Cl. 20.2), the ASN.1 productions
    the tool needs (Cl. 21).
- Robustness: every parser takes `bytes` + offset, bounds-checks every read, and raises a typed `DecodeError`.
  A frame that fails to decode is counted per layer (`metrics.decode_errors`); it never aborts the run.
- Performance target [PROVISIONAL]: 1 GB pcap in < 5 min on a 2020-era laptop, streaming, memory < 500 MB.

## 8. Interfaces

### 8.1 CLI

```
bacnet-health scan    [--interface X | --bind IP/LEN] [--port N] [--target IP ...] [--rate ...]
                      [--read-remote] [--follow-bdt] [--fdr BBMD_IP] [--dry-run] [--yes]
                      [--profile FILE] [-o OUT.json]
bacnet-health listen  [--interface X] [--duration 10m] [-o OUT.json]
bacnet-health analyze CAPTURE.pcap[ng] [--vantage auto|access|span] [--redact-pcap OUT] [-o OUT.json]
bacnet-health report  IN.json [IN.json ...] [--diff PREVIOUS.json] [--redact] [--branding FILE] [-o OUT.html]
bacnet-health audit   [--interface X] [--listen 10m] [scan options] [--branding FILE] [-o DIR]
bacnet-health gui
```

Cross-subnet flags (`--read-remote`, `--follow-bdt`, `--fdr`) need an interactive typed IP confirmation. Non-interactive
use needs `--i-understand-this-crosses-subnets=<IP>`; `--yes` does not cover them (D19). If `--yes` is used, the
interface must be given explicitly, because auto-pick needs a human to confirm it.

### 8.2 GUI (PySide6)

- **Home page**, three large buttons:
  1. **Run health check.** Steps:
     1. Site details and rules-of-engagement (prefilled from the profile).
     2. Interface — auto-picked, the user confirms.
     3. Pre-flight: port free, firewall check, NTP check.
     4. Budget preview, with an optional packet preview.
     5. Start.
     6. Live progress, plus a large Stop button.
     7. Report shown in the app (QWebEngine).
  2. **Analyse a capture file.** Drag and drop, or pick a file. Vantage is shown and can be overridden. If dumpcap or
     tcpdump is detected, a "Full capture (SPAN port)" action is offered (D23).
  3. **Open & compare reports.**
- **Advanced** (collapsed): every CLI option. Cross-subnet actions show a risk explanation, need the target IP typed
  in, and are recorded in the report with user name, time and target.
- **Scan profiles** (`.bhprofile`, JSON) carry every option, plus branding and rules-of-engagement defaults. The owner
  prepares a profile; the onsite engineer double-clicks it and the app opens straight into the health-check wizard.
  A profile can **lock** options so the onsite engineer cannot change them.
- All long operations run in a worker thread that calls the same core API as the CLI. The GUI contains no BACnet logic.
- Plain-English help text sits next to every step. No BACnet jargon on the home path.

## 9. Verification plan

### 9.1 CI layer (every commit; macOS, Windows, Linux; Python 3.10–3.13)

- Unit tests per decoder layer, with golden vectors hand-built from spec examples (Cl. 20 encoding examples
  [TBV location]).
- Synthetic pcap generator (stdlib). For every finding ID: at least one positive case, one negative case, and one
  below-vantage case. Golden JSON outputs are compared field by field.
- Stdlib device simulator. It runs N virtual devices on localhost and answers Who-Is/RP/RPM/Read-BDT/Read-FDT.
  Injectable faults: duplicate instance, no RPM support, slow response, no response, segmentation-required, BBMD with
  asymmetric BDT.
- Fuzzing: random mutation of valid frames, about 100k per CI run. Invariant: no exception other than `DecodeError`.
- Transmit allow-list test: every encoder output passes through `tx_guard`; a static check asserts that no prohibited
  service choice constant appears in an encoder.
- JSON Schema validation of every output.

### 9.2 Oracle layer (before each release; Linux)

- Docker or netns lab, with three subnets joined by bacnet-stack BBMDs and routers, plus bacnet-stack server devices.
- Scenario matrix. Each scenario has its expected findings and must produce zero findings outside that list:
  - clean;
  - duplicate instance across subnets;
  - two BBMDs in one subnet;
  - asymmetric BDT;
  - mixed masks;
  - foreign device registered from a "public" (documentation-range, flagged as public by test config) address;
  - non-standard port;
  - a router with a duplicate network number.
- Differential decoding: every lab and synthetic pcap is decoded with `tshark -T json`, and key fields are compared:
  BVLC function, NPDU control/DNET/SNET, APDU type/service/invoke-ID, object/property IDs.
- Reference readers: bacnet-stack `bacwi`, `readbdt`, `readfdt` against the same lab, compared with our device set and
  tables.

### 9.3 Acceptance criteria for 0.1.0a1

- 100% of expected findings detected in the scenario matrix; 0 false positives in the clean scenario.
- tshark field agreement ≥ 99.9% of frames. Every disagreement must be triaged and explained.
- Self-capture test (§9.4) passes.
- The non-technical reviewer test (§9.5) passes.

### 9.4 Self-capture test

During a lab `scan`, run `tcpdump` on the tool's host. An independent script, using tshark rather than our decoder,
asserts that:

- every frame sent is in the allow-list (§1.1);
- the peak rate stays within the budget;
- after Stop, no frames leave the host later than 100 ms.

### 9.5 Human checks

- A non-technical facility manager reads a lab report and can state the top three problems and what to do next.
- A second BACnet practitioner reviews the finding catalogue (§4).
- Physical-device acceptance (JCI and Carrier) is deferred until hardware or an authorised site is available. The
  README lists validated devices only once they have been tested.
